# Fleetbase on Railway

A one-click [Railway](https://railway.com) template that runs
[Fleetbase](https://github.com/fleetbase/fleetbase) — an open-source logistics and supply-chain
operating system: dispatch, fleet operations, live tracking, storefront/commerce, a REST API and an
extension system. This template deploys the full stack (MySQL, Redis, a realtime socket server, the
API, a queue/scheduler worker and the console UI) with the **owner account created for you at first
boot** and **public self-signup closed**.

## Why the owner account is created for you

Fleetbase's onboarding endpoint (`POST /int/v1/onboard/create-account`) has no "already onboarded"
guard: on a public URL, anyone who reaches the API before you — or after you — can create an account
and an organisation. This template closes that endpoint at the API's front door (`403` unless you
deliberately set `PUBLIC_ONBOARDING=true`) and instead creates the owner account **once, at first
boot, over loopback inside the container**, from the deploy variables. The public URL never serves
the sign-up endpoint, so there is no race with a stranger. Further users are invited from inside the
console by the owner.

## What you get

Six services, wired together:

| Service | What it runs |
|---|---|
| `database` | `mysql:8.0-oracle` on a volume — all business data |
| `cache` | `redis:7-alpine` — cache and queue broker |
| `socket` | `socketcluster/socketcluster` — realtime websocket broadcasting (public domain) |
| `api` | The API (Octane/FrankenPHP) behind a Caddy front door (public domain, uploads volume) |
| `worker` | The stock upstream API image: `php artisan queue:work` plus the `go-crond` scheduler |
| `console` | The Fleetbase Ember console — the UI you log into (public domain) |

Also: a generated `APP_KEY`, a generated `OWNER_PASSWORD`, and health checks and ports wired for
Railway.

## Deploy

1. Click **Deploy on Railway** and fill in **`OWNER_EMAIL`** — the first administrator's email
   address (required). Optionally edit `OWNER_NAME`, `OWNER_PHONE` and `ORGANIZATION_NAME`.
2. Wait for the deploy. The `api` service goes healthy quickly (its front door answers `/healthz`
   itself), but the **first boot runs migrations, sandbox migrations, seeds, permissions and
   extension-registry init — expect several minutes** before you can log in. Watch the `api` logs
   for `owner account created for …`.
3. Open the `api` service → **Variables** and copy `OWNER_PASSWORD` (generated by Railway).
4. Open the **console** service's public domain and sign in with `OWNER_EMAIL` / `OWNER_PASSWORD`.
5. Invite your team from inside the console. Public sign-up stays closed.

Notes:

- **Email.** Outbound mail needs your own SMTP settings (`MAIL_MAILER`, `MAIL_HOST`, `MAIL_PORT`,
  `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM_ADDRESS`). Without them, notifications and
  invitations are written to the log instead of being sent.
- **Routing.** `OSRM_HOST` defaults to the public OSRM demo server
  (`https://router.project-osrm.org`), which is rate-limited and not meant for production traffic —
  point it at your own OSRM instance for real use.
- **Extensions.** The API contacts the Fleetbase extension registry
  (`https://registry.fleetbase.io`) at boot to initialise the registry.

## Security

See [SECURITY.md](SECURITY.md). In short: guard `OWNER_PASSWORD`, leave `PUBLIC_ONBOARDING` at
`false`, and back up both volumes (MySQL data and the API storage volume).

## Local development

```bash
export OWNER_PASSWORD='Change-me-123!'   # local test owner password (never commit one)
docker compose up --build                # all six services: db, cache, socket, api, worker, console
tests/static.sh                          # syntax, shellcheck, compose shape, digest pins, secrets
tests/smoke.sh                           # health, blocked onboarding, owner login, console config
tests/persistence.sh                     # data survives a full restart
```

The console is on <http://localhost:4200>, the API on <http://localhost:8080>. First boot takes
several minutes locally too. `tests/railway-smoke.sh` runs the same checks over HTTPS against a
deployed template.
